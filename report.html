Architecture

BeaconComponents<T>— ref-holder, zero methods
  • OperationsManager<E> — voluntary exits, slashings, BLS-to-exec changes
  • AttestationManager<E> — pools, observed sets, shuffling cache, early attester cache
  • SyncCommitteeManager<E> — sync aggregation pool, observed contributions
  • DataAvailabilityManager<T> — blob/column verification, DA checker, KZG, custody
  • ExecutionManager<T> — proposer cache, fork choice signal, optimistic checks
  • ValidatorQueryService<T> — validator pubkey cache, index lookups
  • CanonicalHead<T> — fork choice, head state, finality
  • store Arc<HotColdDB> — hot/cold database
  • slot_clock — wall-clock slot
  • spec Arc<ChainSpec> — chain specification
  • config ChainConfig — runtime configuration

Context Structs (explicit dependency bundles for testable orchestration)

  • AttestationVerificationContext — all attestation verification (26 call sites migrated)
  • BlockImportContext — 9 block import helper free functions
  • BlockProductionContext — 7 block production helper free functions
  • ExecutionOrchestrationContext — execution layer orchestration

What Changed

  • 6 component structs extracted from BeaconChain — OperationsManager, AttestationManager, SyncCommitteeManager, DataAvailabilityManager, ExecutionManager, ValidatorQueryService. Each owns its state and is constructable with ::new().
  • Attestation verification decoupled — all 26 call sites migrated from &BeaconChain<T> to AttestationVerificationContext.
  • Block import and production converted to free functions — 9 block import helpers and 7 block production helpers use explicit context structs.
  • 15 state query methods extracted to free functions in state_query.rs, taking (store, canonical_head, spec) as explicit parameters.
  • Drop persistence moved to components — OperationsManager, CanonicalHead, and DataAvailabilityManager each persist their own state on drop.
  • 17 thin wrapper methods deleted, 60+ callers migrated across http_api and network crates to direct component access.
  • with_committee_cache deduplicated from 3 implementations to 1 on AttestationManager.
  • Struct renamed from BeaconChain to BeaconComponents — zero impl methods in beacon_components.rs.

Future Work

  • 1
    Promote component modules to separate crates
    Enables parallel compilation. Each component crate builds independently — cuts incremental build times for changes scoped to one domain.
  • 2
    Remove Arc<BeaconComponents> from callers
    HTTP API and NetworkBeaconProcessor hold Arc<Component> directly. Eliminates the last vestige of the god object pattern in caller code.
  • 3
    Remove BlockProductionContext escape hatch
    3 methods still hold a reference to the full chain (is_healthy, get_execution_payload, compute_beacon_block_reward). Extract their dependencies explicitly.
  • 4
    Create SyncCommitteeVerificationContext
    Follow the same pattern as AttestationVerificationContext. 6 functions in sync_committee_verification.rs still take &BeaconChain<T>.
  • 5
    Add more component tests for critical paths
    Expand coverage with standalone construction tests for context structs (not using from_chain). Target edge cases in shuffling cache and DA boundary calculations.
